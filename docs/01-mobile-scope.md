# 平台移动端能力边界

基于现有 `dalian-shipping-smart-ops` 实现梳理，明确哪些能力迁入微信小程序。

## PC 端已体现的移动端约束

`patrol-control.js` 中 `isPatrolMobileContext()` 将以下流程限定为移动端：

| 流程 | 说明 |
|------|------|
| 现场巡检项执行 | 逐巡更点打卡、填报正常/异常、附件 |
| 现场问题复检 | 创建人线下打卡全部关联巡更点后提交 |
| 巡更点顺序 | 支持依次打卡 / 随机打卡（`orderMode`） |

PC 端提示：「现场巡检请在移动端执行」「请使用移动端线下巡更打卡完成复检」。

## 迁入小程序的功能清单

### 巡查管控（一期 · 必做）

1. **我的巡检任务** — 执行人视角，待完成/已超时/已完成
2. **任务详情 & 子巡检项** — 远程/自动只读，现场可执行
3. **现场巡检执行** — 巡更点列表、进度、逐点提交
4. **打卡能力** — 二维码扫码（`wx.scanCode`）、NFC（Android `wx.getNFCAdapter`）、门禁回调（服务端对接）
5. **问题提报** — 巡检异常自动建单 + 临时上报
6. **问题整改** — 问题处理人上传描述/图片/视频
7. **问题复检** — 现场类：巡更点打卡；远程/自动类：确认系统复检结果
8. **排班查询** — 按当前用户查看今日/本周/本月值班
9. **站内信** — 计划提醒、催办、问题流转通知（PC 仅有 `remindChannel` 配置，小程序补全收件箱）

### 巡查管控（一期 · 可选）

- 远程巡检轻量执行（图片/结论填报，视频仍链 PC 或 WebView）
- 任务转派确认（PC 发起，小程序通知新执行人）

### 其他模块（一期 · 工作台入口已预留）

- **消防管理**：报警推送、消防设备、监测统计（对齐火先知 APP 能力）
- **访客管理**：保安扫码核验、今日待访、来访记录
- **工单服务**：我要报修、我的工单、待处理
- **资产管理**：资产盘点（二维码/NFC）、故障报修（手动/扫码）、我的报修（查看记录与审核详情）、扫码查资产；资产类巡更点打卡纳入巡查管控现场巡检

## 工作台结构

按业务模块分区展示入口，配置见 `miniprogram/config/modules.js`：

| 模块 | 入口 |
|------|------|
| 巡查管控 | 巡检任务、扫码巡检、临时上报、巡检问题 |
| 消防管理 | 报警推送、消防设备、监测统计 |
| 访客管理 | 扫码核验、今日待访、来访记录 |
| 工单服务 | 我要报修、我的工单、待处理 |
| 资产管理 | 资产盘点、故障报修、我的报修、扫码查资产 |

顶部保留「巡查管控待办」统计卡片（今日任务/待巡检/已超时/待整改）。

## 角色与入口

同一用户可兼任多角色，工作台按**待办聚合**而非按角色分 App：

| 角色 | 数据来源 | 小程序入口 |
|------|----------|------------|
| 任务执行人 | `patrolTask.executorId` 或班组当日值班 | 首页「待巡检」 |
| 问题处理人 | 子项 `issueHandlerId` / 问题 `patrolIssueHandler` | 首页「待整改」 |
| 问题创建人/复检人 | 问题 `patrolIssueCreatorId` | 首页「待复检」 |
| 任意用户 | 排班表 | 「排班」Tab |
| 任意用户 | 消息中心 | 「消息」Tab |
